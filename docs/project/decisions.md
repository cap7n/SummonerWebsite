# Decision Log

Why things are the way they are. Newest first. When an [open question](open-questions.md) gets answered, it lands here.

| Date | Decision | Why |
|---|---|---|
| 2026-08-01 | **The game is one unified flow**: lobby → **diegetic graveyard hub** (15 tombstones = 6 skeleton / 3 shield / 3 archer / 3 mage items, 4 spell altars — walk up, E to buy; TAB inventory overlay; live item bar with pools + cooldowns) → **deploy circle** (all players inside → 3 s countdown) → generated map where armies come from equipped items and spells cast on keys 1–4. Harnesses stay under the Play button. Ranged units (archers/mages) accepted — the contact-combat fork taken. | "Time to merge the four buttons into something unified" — every proven system now runs *connected*, which is what the one-project rule was for. Spells resolve by ownership law (cast = broadcast intention, each machine applies to crowds it owns), so screen-consistency carries over. |
| 2026-08-01 | **Points are a respendable per-run budget from a host-owned shared pool** — the host's lobby has one total, copied to every player, re-allocated fully each run (every run is a draft). No permanent per-player point meta; permanence comes from world unlocks that stay in the graveyard (e.g. a found merchant). Mods/items trade freely, never bound to each other. | Colleague's adamant call on the shared pool — indulged deliberately, flagged for playtest review ("maybe explore persistent characters" kept open). Draft-every-run keeps builds fluid and makes found points a party-wide reward. |
| 2026-08-01 | **Item system decided**: 3 variants (Summoning items = troop pools with stats/regen, Spell items, Modifiers), **8 item slots** per player each with **4 mod sockets** (panel grows upward to reveal them), items **tradable** between players. [Items](../game/items.md). | Build-is-your-inventory made concrete: the army itself is itemised, so composition, sustain (regen-per-item) and co-op negotiation (trading over 15 scarce graves) all live in one system. |
| 2026-08-01 | **Graveyard economy decided**: **15 graves**; buying one with points grants its item and locks the tombstone to the buyer; more points upgrade it. **Points are the single currency** — start ~10, found *collectively* on runs (everyone's total rises), spent individually. [Graveyard](../game/graveyard.md). | One currency kills the two-currency noise worry; grave locks make meta progress visible in the shared hub; 15 graves < 4×8 slots makes scarcity and trading the party's ongoing conversation. |
| 2026-07-31 | **One project, one build.** No side projects, no parallel builds; systems are folders with test scenes inside the main project, all reachable from one dev launcher. The netcode spike was folded back in the same day. | Two parallel builds made cap7n think the working multiplayer had been deleted. Isolation is still available *on request* — the default is everything together, so "it all works together" is continuously proven. |
| 2026-07-31 | **Map size is a design choice, not a technical limit** — measured: 8 km × 8 km with 7.7 M triangles in frame costs 2.4 ms. No LOD, no floating origin, no level streaming needed. Pick size in *minutes of caravan travel*. [Numbers](../tech/architecture.md#terrain-results). | The terrain system was built and measured rather than guessed at. Rendering never became the bottleneck; generation time and memory did, and both are one-off loading costs. |
| 2026-07-31 | **Terrain LOD and chunk skirts removed after measuring** — LOD was slower than no LOD (the GDScript pass cost more than the triangles it saved). | "Simple until proven boring" applied to tech: they were built, measured as net-negative, and deleted. Per-chunk custom AABBs were kept, because vertex-shader displacement is invisible to the engine's culling. |
| 2026-07-31 | **Summoners are wizards with hardcore [spells](../game/summoner.md#spells)** — the game is horde *plus* magic. The feeling chased is **power**: overwhelm in bodies and spells, *if you prepared*. | Completes the fantasy and gives the passive bubble a second active verb. Spell source/costs/targeting all [open](open-questions.md#spells--power); Total War-style stalemate combat is leaning-rejected in the same breath. |
| 2026-07-31 | **Maps are procedurally generated**: noise heightmap + generated road graph + hand-authored POI stamps. [Runs](../game/runs.md#map-generation). | Hand-building maps is the team's declared weak spot; procgen converts it into replayability. The no-navmesh tech stack makes generation nearly free (no bake step), and authored POI stamps keep quality where gameplay happens. |
| 2026-07-31 | **The graveyard hub is a real shared space — all 4 players spawn there before a run.** The hub is the lobby. Rebuild structure added to the game project (graybox Hub scene). | A hub you stand in together beats a menu; it also gives the lobby a place and the meta a stage. |
| 2026-07-31 | **Troops are entities on the wire: per-troop quantized streaming** (6 B/troop, 15 Hz deltas + 1 Hz keyframes). Shape-sync and lockstep rejected. | New hard requirement: **battles must look identical on every screen** — locally-grown crowds can't guarantee it, one authoritative sim per crowd can. Lockstep would need a determinism Godot doesn't offer and adds WASD latency. Spike measured ~0.2 Mbit/s host upload per client — 10× under budget. [Networking](../tech/networking.md#the-troop-sync-problem). |
| 2026-07-31 | **Simulation is partitioned by ownership**: your machine sims your bubble, host sims the world (enemies, caravan, fog, POIs). | Zero input lag on your own army, host CPU shared across all machines the sane way, and screen-consistency falls out for free — there's only one version of any fight. |
| 2026-07-31 | **Boids + heightmap + local avoidance for troops; no navmesh pathfinding.** Long-range movers (caravan, enemy packs) use a small authored **route/road graph**. | Troops never navigate alone — they follow, which is local steering. Skips navmesh baking on generated maps entirely; roads make caravan routing a visible player decision. |
| 2026-07-31 | **Troops are data, not nodes**: packed arrays + spatial grid + one MultiMesh per crowd. No physics bodies. | Spike measured ~2 ms/frame for 660 agents in plain GDScript — 1000+ agents fit with headroom. Per-troop nodes/physics would not. |
| 2026-07-31 | **Rebuild proceeds as isolated systems, each with its own test scene**, connected by events; networking ports last. Build order on [Architecture](../tech/architecture.md). | Developer's preferred way of working ("build systems, not full games"), and both rebuild-blocking spikes passed on 2026-07-30/31 — including a stable real-internet Steam session (one stutter found, fixed with sender-tick timestamps). |
| 2026-07-30 | **The bubble is simplified to a passive aura** around the summoner — no move orders, no stretching. Both control schemes [parked](../game/bubble.md#parked-prototype-systems); the F1 A/B closes without a winner. | Keep it simple, at least for now. The game's decisions moved up a layer (composition, caravan, map routing), so the bubble doesn't need to carry the tactical load. Parked, not deleted — the code and findings stay. |
| 2026-07-30 | **Runs are hub-and-sortie from a Graveyard**, which doubles as the meta-progression hub: **tombstones** levelled with **points** to strengthen units and unlock unit types; starting items picked there. | Answers the run-structure question and the "what persists" question's backbone in one move, and the hub is thematically the game itself — a graveyard that grows *is* the save file. |
| 2026-07-30 | **A caravan is the run's fail state**: shared, commandable by any player, guarded by its own troops; if it dies the run ends. | Gives a big map a spine and real pressure, ties four split-up players together, and supplies the moment-to-moment tension the simplified bubble gave up. |
| 2026-07-30 | **Maps are big RTS levels with POIs** (objective → reward), Helldivers-shaped. | Makes travel a cost and routing a decision; scales naturally to four players who can split up. |
| 2026-07-30 | **Fog of war with fully shared vision** — anyone reveals for everyone. | Splitting up stays readable, removes "where are you?" friction, and costs one fog state on the wire instead of four. |
| 2026-07-30 | **Camera locks to your character or unlocks to free-roam the map**, RTS-standard. | Already built and proven in the PoC; on big maps free-look is how you read the map and watch the caravan. |
| 2026-07-30 | **Co-op is 4 players** (1–4; solo is a lobby of one). | The pillar was always "play it with friends"; 4 is the party size the fantasy wants. Cost is architectural (200+ troops), and it's cheaper to pay for it now than to retrofit. |
| 2026-07-30 | **Anti-cheat is out of scope.** | Private co-op sessions, no ladder or economy — nothing to protect. Buys client-authoritative ownership of your own summoner/bubble (zero input lag, no reconciliation). |
| 2026-07-30 | **Reuse OTR's network stack** — GodotSteam `SteamMultiplayerPeer`, one `NetworkTickManager`, `StateBuffer` + Hermite interpolation, per-entity sync ownership. | Already built, shipped and debugged by the same developer in the same engine. Zero novel transport risk; the only genuinely new problem is troop volume. See [Networking](../tech/networking.md). |
| 2026-07-30 | **Wiki created** (this site), mirroring the TowerDrop wiki stack (MkDocs Material, same conventions). | One place for design truth before the feature set grows. |
| 2026-07-30 | **Both control schemes wired into one build behind F1**, instead of two builds. | A/B testing feel needs instant switching in the same battle; export-per-tweak kills iteration. |
| 2026-07-30 | **PoC is disposable; rebuild planned** on an architecture the developer understands and helps shape. | The prototype answers feel questions; it shouldn't calcify into the codebase. |
| 2026-07-29 | **Stretch release rule:** releasing retracts the pod *unless* it touches an enemy bubble — then it latches until right-click breaks it. | Makes the stretch a commitment gesture with a natural "grip" metaphor; severing deferred to [open questions](open-questions.md#severed-pods). |
| 2026-07-29 | **Pod-only contact commits only pod troops**; disc contact commits everyone. | Turns the stretch into a probing weapon with a reserve, instead of an all-in trigger. |
| 2026-07-29 | **Bubble invariants:** never faster than the summoner; summoner never outside the bubble (hard leash). | The army is an extension of the summoner, not an independent RTS unit. |
| 2026-07-29 | **Troops walk back into formation** (speed-capped regroup) instead of lerp-snapping. | Snap-back after fights broke the "living crowd" illusion. |
| 2026-07-29 | **Stretch system chosen as the direction to explore** over plain click-to-move (kept as A/B baseline). | The teardrop stretch is the game's identity mechanic; click-move is genre-standard. |
| 2026-07-29 | **Palette is dark green.** Not blue. Ever. | Developer preference, strongly held ("i hate bleu xD"). Troops green, summoner gold for contrast, enemy red. |
| 2026-07-29 | **Godot 4.7** for the PoC (over Unity 6, which is also installed). | Existing Godot familiarity and project folder already prepared. |
